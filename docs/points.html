Survey Points to Polygons

Turns an Emlid GNSS point export into SU and Feature polygons.

This was Emlid to SU before 1.1.0. It now reads feature outlines as well as SU outlines, and uncrosses an outline that was shot out of order.

Overview

Two modes:

ModeWhat happens
Replace geometry on existing layer(s) Matches records by number and swaps in the new outline. Never adds rows, never edits attributes. By default the changes sit in the layer's edit buffer so you can look at them before keeping them.
Build polygons on new temporary layers Connect-the-dots with no target and no matching. Writes one fresh in-memory layer per point type (EPSG:32636) carrying the number, the vertex count, and how many crossings were undone. Nothing on disk is touched.

Input can be one file, several files at once, or a point layer already loaded in the project. With several files the points are combined and grouped across all of them.

CSV and Excel are read through GDAL/OGR, which QGIS already ships. No pandas or openpyxl needed.

Two kinds of outline, one run

A day's export mixes both kinds of outline point, so one run reads both and writes each to its own layer:

PointsName formGoes toMatched on
SU outlines SU_[Field].[SU]-[n] the SU layer its SU field
Feature outlines F_[Field].[Feature]-[n] the Features layer its Feature field

SUs and features are numbered independently — SU 55 and Feature 55 are unrelated — so they always go to separate layers. Untick either type to skip it. Pointing both at the same layer is refused rather than filing feature numbers as SU numbers.

Every other coded point in the export is ignored: E_ elevations, O_ finds, P_ pails, GCP_ control, S_ samples, SEC_ section references.

The crossover check

If the points weren't shot walking cleanly round the perimeter, connecting them in increment order makes the outline cross itself — a bowtie. The tool finds those crossings and reorders the points to undo them before building the polygon.

It reorders as little as it can: it reverses the run of points between two crossing edges and nothing else, so an outline that was shot correctly comes out untouched, and a concave one stays concave instead of being rounded out. Every fix goes in the log with the increments involved:

[WARNING] SU 1355: the outline crossed itself; reordered the
points to uncross it (1 fix(es)). Increments are now connected
1, 2, 5, 4, 3, 6 instead of 1, 2, 3, 4, 5, 6 — check the result
against the shots before saving.

It is worth checking those. The reordering removes the crossing, but only you know which shape you actually dug — turn on QC points and compare. QC layers always show the shots as recorded, so they are the reference to check a reordered outline against.

For scale: 74 of the 486 outlines in the seasons archive cross themselves.

Tutorial

Open it

Plugins → TKAP Tools → Survey Points to Polygons…

Pick what to do

Choose Replace geometry on existing layer(s) or Build polygons on new temporary layers. In temporary-layer mode the target and replacement-rule options switch off and you can name the new layers.

Point it at your survey data

Browse to one or more CSV/Excel exports, or pick a point layer from the project. Each source needs a Name column and either Longitude/Latitude or Easting/Northing. Lon/Lat is preferred, and gets reprojected from WGS84 into EPSG:32636.

Set the targets

Replace mode only. Each ticked point type gets a target polygon layer and the field on it holding the number. Both are preselected for you: whichever polygon layer carries an SU field is offered for SU points, and whichever carries a Feature field for feature points. If nothing matches, the box is left empty rather than guessing.

Choose the replacement rule

  • Replace geometry regardless: overwrite the shape of any match, whether or not it had one.
  • Only fill empty / missing geometry: fill records whose geometry is empty or NULL, leave the rest alone.

The rule applies to both targets.

Optionally add QC points

Drops a point layer per outline with the raw vertices, so you can check the shape against the original shots — QC_SU_1355, QC_F_55. Leave the folder blank for in-memory layers, or point it at a folder to write shapefiles.

Run, then review

Read the log: it names every outline it uncrossed, skipped, or couldn't match. In replace mode the new outlines are staged in each layer's edit buffer. Keep them with Save Layer Edits (the disk icon on the Digitizing toolbar), or discard by toggling editing off without saving. There's a checkbox to commit straight to disk if you'd rather skip the review.

If a target layer is already in an edit session, the changes join that buffer. The tool never force-saves.

Point naming

All of these read as the same SU:

SU_6.1355-1     the full form
SU_1355-1       the shorthand

And these as the same feature:

F_2.55-1        the full form
F_55-1          the shorthand

The increment is the last number, the SU or feature number is the number before it, and any leading field number is ignored. Separators and zero-padding are lenient, so the variants that actually turn up in the exports all parse: F-1.25-9, F_1.19.12, SU_1355 1, SU_01355-1, SU#6/1355:1.

What it won't accept is a letter sitting where only numbers and separators belong, so SU_2.115new-1 and F_5.SU-719.xxx.1 are rejected with a warning rather than being misread as some other number.

Each outline needs at least three points.

What it skips

  • A number with no matching record in its target layer, or matching more than one.
  • An SU- or F-prefixed point that isn't an outline vertex, like a single labelled shot with no increment. Skipped with a warning; the rest of the file still runs.
  • An outline whose points repeat an increment number, since the order is ambiguous. That one outline alone is skipped.

Only a genuinely unusable table stops the run: one missing Name, or missing both coordinate pairs.

Known limits

  • Uncrossing produces a polygon that doesn't cross itself, which is not always the one you dug. Check the result against QC points before saving.
  • A point layer loaded in the project is read from its Name and coordinate columns, not from its geometry.
  • If a target layer's CRS can't be resolved, the tool assumes it already matches EPSG:32636 rather than reprojecting.
