Emlid to SU

Turns an Emlid GNSS point export into SU polygons.

Overview

Two modes:

ModeWhat happens
Replace geometry on an existing SU layer Matches records by SU number and swaps in the new outline. Never adds rows, never edits attributes. By default the changes sit in the layer's edit buffer so you can look at them before keeping them.
Build polygons on a new temporary layer Connect-the-dots with no target and no matching. Writes to a fresh in-memory layer (EPSG:32636) carrying the SU number and vertex count. Nothing on disk is touched.

Input can be one file, several files at once, or a point layer already loaded in the project. With several files the points are combined and grouped by SU across all of them.

CSV and Excel are read through GDAL/OGR, which QGIS already ships. No pandas or openpyxl needed.

Tutorial

Open it

Plugins → TKAP Tools → Emlid to SU…

Pick what to do

Choose Replace geometry on an existing SU layer or Build polygons on a new temporary layer. In temporary-layer mode the target and replacement-rule options switch off and you can name the new layer.

Point it at your Emlid data

Browse to one or more CSV/Excel exports, or pick a point layer from the project. Each source needs a Name column and either Longitude/Latitude or Easting/Northing. Lon/Lat is preferred, and gets reprojected from WGS84 into EPSG:32636.

Set the target

Replace mode only. Pick the polygon layer to write into and confirm which field holds the SU number; it defaults to SU. Matching is on the SU number alone, with no field or trench designator.

Choose the replacement rule

  • Replace geometry regardless: overwrite the shape of any matching SU, whether or not it had one.
  • Only fill empty / missing geometry: fill records whose geometry is empty or NULL, leave the rest alone.

Optionally add QC points

Drops a point layer per SU with the raw vertices, so you can check the outline against the original shots. Leave the folder blank for in-memory layers, or point it at a folder to write shapefiles.

Run, then review

In replace mode the new outlines are staged in the edit buffer. Keep them with Save Layer Edits (the disk icon on the Digitizing toolbar), or discard by toggling editing off without saving. There's a checkbox to commit straight to disk if you'd rather skip the review.

If the target layer is already in an edit session, the changes join that buffer. The tool never force-saves.

Point naming

Both of these read as the same SU:

SU_6.1355-1     the full form
SU_1355-1       the shorthand

The increment is the last number, the SU is the number before it, and any leading field number is ignored. Separators and zero-padding are lenient, so SU_1355 1, SU-1355-1, SU_01355-1 and SU#6/1355:1 all parse. Anything not starting with SU is ignored.

Points need to be recorded walking the perimeter in increment order, since the tool connects them in that order. Each SU needs at least three points.

What it skips

  • An SU with no matching record, or matching more than one.
  • A SU-prefixed point that isn't an outline vertex, like a single labelled shot with no increment. Skipped with a warning; the rest of the file still runs.
  • An SU whose points repeat an increment number, since the outline order is ambiguous. That SU alone is skipped.

Only a genuinely unusable table stops the run: one missing Name, or missing both coordinate pairs.

Known limits

  • No self-intersection check. A bowtie depends on the order the shots were walked.
  • If the target layer's CRS can't be resolved, the tool assumes it already matches EPSG:32636 rather than reprojecting.
