Stratigraphic Phasing

Splits Stratigraphic Units into one layer per phase.

Overview

ActionWhat it does
Split by Phase…Builds the per-phase layers for one excavation field.
Export Phase Plans…Exports one plan per phase using a print layout you designed.

The space_phase field holds a comma-separated list, one entry per space the SU belongs to:

Sp.85.3 (Abandonment), Sp.85.1 (Construction), Sp.85.2 (Occupation)

Each entry becomes a (space, phase) bucket, and each bucket becomes one output layer, e.g. Field6_Sp34_Phase1_Construction.

Grouping is per space, not per phase number. Phase numbers run independently within each space, so Sp.33.1 and Sp.34.1 are unrelated moments and stay in separate layers.

An SU can appear in several layers. One in several spaces lands in each space's layer, and one listed for several phases within a space (a wall built in one phase and still standing later) lands in every phase it lists. Geometry is duplicated across those layers, so the output feature count is higher than the input SU count.

area in TKAP data. The value list is read live from the layer, with numeric values sorted numerically.

Read the preview

Live filtered layers point at the same source with an editable filter, so nothing is copied. So Field6_Sp34_Phase1_Construction is really:

"area" = '6' AND "space_phase" LIKE '%Sp.34.1 (%'

Open Layer Properties → Source → Query Builder on any phase layer to add your own clauses. Because these address the same table as the source, they're locked read-only. Toggle Editing is disabled so an edit session can't reach production data. The filter stays editable; only the features are protected.

Temporary scratch layers are a frozen in-memory copy. Editable, because editing a copy can't reach the original. Gone when you close QGIS unless you save them.

GeoPackage writes every phase as a separate table in one .gpkg. The tool refuses to write to the source layer's own file.

Run

Output layers inherit the source layer's renderer, labelling, opacity and blend mode, so they look like what you started from. Turn that off with Inherit symbology from the source layer.

Tutorial: Export Phase Plans

The tool doesn't invent a layout. Design one print layout in QGIS the way you want the plans to look, with north arrow, scale bar, legend and title block, and this walks the phase layers, showing one at a time, exporting a file for each.

Pick the group and the phases

Choose the group of phase layers and tick which ones to export.

Optionally pick a Features group

Features have no space_phase attribute, so they can't be split the way SUs are. Build the per-phase feature layers yourself, put them in a group, and point Features (optional) at it. Name each one after the phase layer it belongs with. Matching runs in this order:

OrderFor phase layer Field6_Sp34_Phase1_Construction
1. Same nameField6_Sp34_Phase1_Construction
2. Same name, any punctuation or casefield6 sp34 phase1 construction
3. Space and phase anywhere in the nameFeatures_Sp34_Phase1

Both the Sp and Phase numbers have to match. A phase with no features layer still exports, SUs only.

Pick your print layout

Set up the title, if you want one

Add a text item to your layout and type Title in it. That's the setup. The tool finds any label whose text is exactly that, rewrites it per phase, and puts Title back at the end. A label with the item id phase_title is always matched too.

Replace with: is a template. The default renders as Field 6 - Space 34, Phase 1 (Construction):

{field} - Space {space}, Phase {phase} ({phase_name})

Placeholders: {field}, {space}, {phase}, {phase_name}, {layer}, and \n for a line break.

Choose folder, format and DPI

JPEG by default. PNG, PDF and SVG also available.

Preview, then export

Preview… steps through the phases with Previous/Next, reporting the SU count and which features layer matched. It runs the same code path as the real export, so what you see is what gets written.

Output is one file per phase, named after the layer. Layer visibility, layer names, title text and legend state are all restored afterwards.

Output columns

Each output layer carries the source attributes plus three provenance columns, toggleable in the dialog. On live filtered layers these are virtual fields held in the QGIS project, so nothing is written to PostGIS.

ColumnMeaning
ph_spacespace number this layer represents
ph_numphase number within that space
ph_namephase name

Warnings

Non-fatal data problems show in the dialog and in Log Messages under the TKAP Phasing tab:

  • a space_phase with text the parser couldn't consume, usually a value truncated by a 254-character shapefile export. The parseable entries are still used;
  • a (space, phase) pair with conflicting phase names across SUs. The first-seen name is used;
  • an SU with no geometry.

SUs with a blank space_phase are counted as unphased and skipped.
